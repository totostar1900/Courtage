# Plan — étude IFC en ligne

Spécification : `docs/specs/2026-09-26-plateforme-et-etude-ifc-design.md`.
Méthode : tests d'abord, suite verte avant chaque commit, un commit par tâche
avec le message indiqué.

## Tâche 1 — Moteur actuariel et tests de référence

- [x] Squelette `api/` (pyproject, src/courtage, pytest).
- [x] Référentiel minimal en fichiers : table TV CIMA F, barème CCI Côte
      d'Ivoire (`valide`), barème APB Madagascar (`valide`), turnover plat 2 %.
- [x] `courtage.actuariat.ifc.evaluer()` : fonction pure, détail par salarié,
      totaux entiers.
- [x] Fixture AZITO (23 salariés au 31/12/2019, probabilités de présence du

      cotisation nulle quand le fonds couvre.

Commit : `feat(actuariat): moteur IFC et tests de référence AZITO`

## Tâche 2 — Référentiel versionné

- [x] Format d'un barème validé par Pydantic : pays, code, statut, vigueur
      (du … au …), sources citées, note de vérification, barème typé
      (`tranches_cumulatives` | `paliers`). Tranches et paliers ordonnés,
      taux bornés, vigueur cohérente.
- [x] Chargement d'une version complète ; refus d'un barème mal formé et de
      deux versions d'une même convention qui se chevauchent.
- [x] Barèmes camerounais trouvés en ligne : commerce 2012 et 2024
      (changement au 16/01/2024), banques 2021 (`valide`) et 2024
      (`a_valider` : révisée le 18/11/2024, barème non publié).
- [x] `motifs_de_refus(convention, pays, date)` : `pays_different`,
      `convention_a_valider`, `hors_vigueur`.

Commit : `feat(referentiel): versions, barèmes et règle d'émission`

## Tâche 3 — Lecture et contrôle du fichier du personnel

- [ ] Contrôles bloquants et avertissements de la spec §6, chacun testé.
- [ ] Rapport de contrôle : ligne, colonne, message.

Commit : `feat(fichier): lecture et contrôle du fichier du personnel`

## Tâche 4 — Base de données

- [ ] Test : une organisation ne lit pas les données d'une autre.
